# 验证范围与已知问题

当前发布：0.2.3。以下是已完成的检查及其边界，不是全设备兼容或生产可用保证。

## 自动检查

- 管理器与独立 helper 的 Go 测试、race 检查和 go vet。
- 使用官方 dae v2.1.1、Mihomo v1.19.33 与 helper 做配置解析、MRS 解码和 DAT 原生引用集成测试。
- Web JavaScript 语法、安装脚本 shell 语法、公开文件清单和发布包校验和。
- Linux 十种目标架构交叉编译；交叉编译成功不等于对应硬件运行验证。

持续集成状态以仓库 Actions 为准；测试程序及流程见 CONTRIBUTING.md。

## 已做的实机检查

在 PVE 独立 Debian 12 虚拟机、Linux 6.12 内核和局域网测试客户端上，检查过管理登录、原生校验、订阅拉取、选择策略、配置编辑、回滚和后台页面。

透明路径中检查过 DNS、普通 HTTPS、部分国内与海外网站，以及部分 VLESS / Hysteria2 节点。Netflix 的连接情况受节点影响，不承诺地区解锁、流媒体长期稳定或所有协议都可用。未将逐节点全业务测试作为已完成事项。

## 已知边界

1. **配置应用默认重启核心，会短暂断流。** 在测试环境，热重载后曾出现大型 HTTPS 响应异常，重启可恢复，因此保留可选热重载而不默认启用。
2. **少量透明 HTTPS 连接出现过路由/连接跟踪异常。** 相同出口的独立代理请求成功不能证明 eBPF 透明路径正常；需结合核心日志、宿主路由和真实客户端复现。当前没有端到端业务健康探针自动回滚。
3. **测速方法不同。** 核心健康分数来自日志；手动首次请求、连接复用和其他核心的测试结果不可直接比较，详见 LATENCY.md。
4. **日志有观测限制。** 流量或 DNS 绕过本机、缓存、加密 DNS、日志级别和硬编码 IP 都可能导致域名检索为空。IP 关联 Netflix 等业务只是推断。
5. **迁移不完全等价。** fallback、load-balance、DNS 多上游、某些传输和策略参数存在差异。源配置具体是否可迁移应以本次转换报告为准。
6. **平台覆盖有限。** systemd Debian 虚拟机已实测；OpenWrt/procd、其他 CPU、容器及特定固件仍需管理员验收。Windows/macOS 不运行 dae 核心。

## 使用前验收

按 ACCEPTANCE.md 从一台测试客户端开始，至少验证 DNS、TCP/UDP、常用业务、IPv6、策略切换、订阅失败回退和设备重启。语法通过、服务 active、HTTP 202 都不能单独证明整个网络正常。
