# 上线前验收与需要考虑的事项

这份清单对应实际部署决策。“全部完美”无法由配置语法校验保证；应在目标设备、真实拓扑和节点条件下验收。

## 环境

1. 保存 `/etc/config/network`、`firewall`、`dhcp` 及原代理配置；保证有备用管理 IP/有线连接。
2. `uname -r` 与 `dae-manager doctor` 检查内核、BTF、kprobe、cgroup、TC、BPF stream parser；缺失时换兼容内核/固件。不得跳过错误只看版本号。
3. `df -h` 检查闪存/overlay 空间，检查 RAM 峰值和 zram/swap；不要在已接近满盘的路由器上安装整套解码器及 geodata。
4. 核对网卡名字、桥接/VLAN、PPPoE、主路由/旁路由位置、客户端网关、转发和 NAT。检查硬件/软件 flow offload 对 eBPF 和网络策略的影响。
5. 先停止或隔离原透明代理规则，再启动 dae；不要同时运行多个程序接管同一 LAN/DNS 流量。安装器只检测并提示，不自动停原服务。

## 功能

1. 确认后台登录、原生校验、系统信息、节点、策略组和主配置规则数量与预期一致。
2. 在一台测试客户端上确认国内域名直连、常用海外业务分组出口、广告拦截策略、内网静态 hosts、自有内部 DNS 策略（如有）正常。
3. 分别测试 TCP、UDP/QUIC、大文件、长连接与游戏；测试每种节点协议及 Hysteria2 跳端口。不要把“节点被导入”当作节点连通。
4. 在后台切换某个 select 组到 DIRECT、另一个自动组或指定节点，确认新连接出口变化；已有连接不一定立即切换。
5. 测试订阅更新后手动选择是否保留；节点消失应报错并保持旧配置，不能无提示跨地区换出口。
6. 用 `nslookup 内网域名 路由器地址` 和外部域名检查 DNS 5353→5354 链路；关闭备用上游。测试客户端 DoH/DoT、IPv6 与硬编码 DNS 的绕过路径。
7. 原配置 IPv6=false 不等于整个网络禁用 IPv6。核对 RA、DHCPv6、NDP、AAAA、已有 IPv6 连接和 IPv6 防火墙。
8. 临时开启 debug，按 DNS、域名、IP、多个关键字检索；确认核心日志轮转。完成后恢复 info，避免闪存磨损和访问记录长期积累。

## 故障

1. 错误订阅、空订阅、损坏 MRS、网络超时：旧配置必须仍在 current，核心继续使用旧节点。
2. 输入无效规则或引用不存在的组：必须阻止应用，错误可在后台任务中看到。
3. 恢复上一版本：应恢复配置、源 YAML、手动选择和运行参数；验证出口确实回到预期。
4. 重启管理器/设备：确认管理器和核心的自启选择、DNS 前置可用、每天任务没有重复执行。
5. 核心无法启动：查看系统日志及核心日志；停止反复 respawn，检查内核能力、BTF、网卡和冲突。
6. 重载命令成功只说明程序接受配置，不保证公网连通。当前版本没有独立的端到端出口健康探针或自动按业务连通回滚，这一项需要实机人工验收。

## 安全与维护

- 只在回环/可信 LAN 管理；SSH 隧道或 HTTPS；不要开放 WAN 管理端口。
- 备份包含订阅 token、节点密码、私有 DNS 路径和内网拓扑，按私密资料保管。
- 每个新设备重新生成管理口令；不要复制整个 state 目录到多台设备而共用口令。
- 未关闭软件源签名验证，也不会为兼容节点全局关闭 TLS 校验；无法兼容的证书/参数应修复或换节点。
- 核心版本、BTF、kmod 与操作系统更新应有回退方案；管理器和核心分别备份。
- 规则源每日更新可显著增加下载、解码与内存消耗；默认仅更新节点。需要安全规则及时更新时显式开启，并监控失败。

## 退回原网络

1. 停止并关闭 dae-managed 自启：`dae-manager ctl service stop`、`dae-manager ctl service disable`。
2. 恢复原 dnsmasq/DHCP/网关/防火墙配置，重启相关服务。
3. 恢复原代理服务；验证 DNS、内外网和管理页面都能访问。
4. 确认稳定后再停管理器。不要先停 DNS 前置导致所有客户端解析中断。

卸载按需要停止/禁用 `dae-manager` 和 `dae-managed`，移除对应服务定义后保留 `/etc/dae-manager` 私密备份。此版本不提供一键删除配置，避免误删恢复材料。
